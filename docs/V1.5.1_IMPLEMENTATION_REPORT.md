# INGENIUM+ v1.5.1 implementation report

## Outcome

v1.5.1 is the unified public, database-backed INGENIUM+ platform. It preserves the open discovery experience while adding authenticated Student and Staff workflows behind server-enforced roles. The canonical source is the `main` branch and the canonical deployment is the public Site configured in `.openai/hosting.json`.

## Persistence and deployment data

- A D1 migration creates organisations, profiles, memberships, Student/Staff profiles, versioned catalogue content, relationships, collaboration calls, module proposals, documents, ingestion/extraction state, review decisions, refresh state, recommendation evidence, audit events, rate limits and system state.
- An idempotent deployment-time migration seeds 226 published records, 1,007 relationships and 159 evidence sources, together with the supporting organisations, semantic feature vectors and refresh schedules represented in the generated seed.
- The owner bootstrap creates the first authenticated profile and grants the owner the student, staff and administrator roles exactly once. Non-owner requests cannot trigger it.
- R2 is bound as private document storage. Objects are addressed by server-generated keys and are not public URLs.

## Student mode

Student mode stores a private recommendation profile with interests and practical constraints, including study level, language, delivery/travel preferences, home institution, semester timing and credit considerations. Eligibility filters run before ranking. Recommendations carry reasons and score components; feedback can be recorded. Existing browser-local planning remains available but is distinct from authoritative enrolment.

## Staff mode

Staff mode supports opt-in academic discovery, offered and sought expertise, collaboration calls, module proposals, supporting documents, expressions of interest, review status and data-health operations. A contributor cannot self-publish. Accepted updates create versioned public records; rejected or pending revisions do not overwrite the currently published version.

## Documents and review

Upload checks cover allowed metadata, filename/type consistency, file signatures, size, duplicate SHA-256 and permission/rate-limit boundaries. Accepted bytes go to private quarantine in R2 and the metadata is recorded in D1. Protected downloads require an authorised session. Review decisions and mutations produce audit evidence. Files are not represented as malware-clean or extracted until trusted external services report that outcome.

## Recommendation system

The engine combines controlled semantic feature vectors, lexical/topic overlap, graph proximity, practical suitability and academic complementarity. Eligibility filters precede ranking. Staff discovery is opt-in, rankings are deterministic for the same inputs, and reasons are exposed. The synthetic evaluation reproduced on 20 September 2026 achieved recall@3 of 1.0, NDCG@3 of 0.9598603945740938, zero eligibility violations, full coverage and a 0.2976823159797296 NDCG improvement over the lexical baseline. This is a technical fixture result, not evidence of real-user impact.

## Refresh and data health

Twenty-five schedules identify official-source checks. Manual refresh is available to an authorised operator. The refresh service uses timeouts, bounded retry evidence, checksums and snapshots and creates proposals for review rather than silently publishing source changes. The Data Health view exposes schedules, stale/changed evidence and review status. No cloud automation is currently attached to trigger these schedules automatically.

## Backup and recovery

The repository includes a non-production backup/restore verifier and operational documentation. The reproduced test restores 226 content records. This archive deliberately excludes the live D1 database, owner identity, private email, uploaded documents, R2 objects and audit history.

## Material fixes made during delivery

- The initial local dependency tree was inconsistent and caused Rolldown/RSC resolution failures. Clean Node 22 installs and the consolidated repository removed that environmental failure.
- Authentication was changed from an assumed sign-in flow to trusted Sites identity plus an idempotent owner bootstrap so the owner can enter Staff mode on first authenticated load.
- Catalogue seeding moved into the deployment migration so the platform is usable immediately after deployment rather than depending on an unavailable manual session action.
- The production dependency set was updated and verified with a production audit reporting zero known vulnerabilities.

## Verification summary

The release is verified with the repository's current automated test suite, type checking, production build, rendered-route checks, lint, backup/restore checks, recommendation evaluation and source validation. A separate production-style isolated test previously verified authenticated staff access plus PDF upload/download integrity; no synthetic document was retained in production.

## External requirements still open

An approved malware scanner, OCR/document extractor and automatic cloud scheduler are not connected. Uploaded files must remain quarantined pending scanning and independent review. Formal privacy, ownership, retention, support and institutional-adoption decisions remain outside the software implementation.
