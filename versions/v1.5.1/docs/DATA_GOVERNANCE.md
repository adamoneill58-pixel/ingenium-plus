# Data governance

## Data classes

| Class | Examples | Publication rule |
| --- | --- | --- |
| Verified public content | Official programmes, modules, calls, alliance sources | Independent review and published version required |
| Calculated content | Status from dates, recommendation scores, graph proximity | Label as calculated and retain inputs/version |
| Sample/demo | Fictional students and chats | Visible sample label; never convert to real identities |
| Private profile | Student goals, academic matching preferences | Authenticated owner and authorised services only |
| Restricted operational | Drafts, review notes, audits, unscanned documents | Role-controlled; never public |
| Potentially confidential source | Uploaded institutional document | Quarantine, approved scanner, classification and human review |

## Provenance and responsibility

Every published content record links to a source and immutable version. Refresh changes are proposals, not verified facts. The reviewer owns the publication decision; the source owner remains responsible for authoritative academic details. INGENIUM+ is responsible for faithfully presenting the approved record and maintaining the audit trail.

## Retention proposal requiring institutional approval

- Authentication profile: account lifetime plus an agreed short closure period.
- Student recommendation profile and feedback: account lifetime; user deletion/export workflow required before pilot.
- Staff public profile: until opt-out, role ends or source owner withdraws it.
- Drafts and review decisions: seven years is a proposed audit period, not yet approved.
- Rejected/quarantined documents: proposed 90-day retention unless legal/records policy requires otherwise.
- Audit events: proposed seven years, access restricted to authorised operations/security staff.
- Refresh response bodies: not stored in v1.5.1; only checksums and run facts are stored.

## Rights and control

Before real users are invited, the institution must name the data controller and processors, approve the privacy notice, define access/export/correction/deletion routes, establish a lawful basis, complete a DPIA screening and publish incident contacts. Discoverability must remain opt-in and revocable. Revocation removes a staff profile from future collaborator candidate queries immediately.

## Institutional decisions still required

- Controller, joint-controller and processor roles across ten universities.
- Which organisation verifies each membership and which domains are acceptable.
- Accepted document confidentiality classes and prohibited uploads.
- Approved malware scanner and document extraction processor.
- Retention, deletion, legal hold and subject-access procedures.
- Review service levels and responsibility for academic accuracy.
- Whether any contact fields may be shared and under what consent.
- Pilot protocol, recruitment, evaluation rubric and incident escalation.
